Competitions are the tenancy unit: each has its own challenges, roster,
teams, scoreboard, settings, and staff. **Admin → Competitions** manages
them site-wide.

## Creating

Creation asks for the basics and which **optional modules** the event gets
(automations, feedback, analytics, certificates, reports, AI assistant —
each toggleable later in the event's own Settings → Modules). Everything
else — schedule, rules, visibility, brackets — is configured on the
competition itself afterwards, usually by its judges.

## Access

A competition is **public** (listed, joinable) or **invite-only** via
invite codes. Public registration being open or closed (chapter 2) composes
with this: a closed site with an invite-only competition is a fully
provisioned, private event.

## Cloning

**Clone** copies a competition's structure — challenges and configuration —
into a new event without participants, teams, or solves. It's the fast path
for recurring events: clone last year, refresh the content, publish.

## Archiving and deletion

- **Archive** closes a finished event and removes it from active lists;
  everything is retained and it can be unarchived at any time — unless the
  site's **data-retention policy** (chapter 2) is on, in which case the
  archive dialog shows the exact date the event will be purged.
- **Delete** is immediate and permanent — challenges, solves, teams, the
  lot. Prefer archive unless you genuinely need the data gone; if you might
  ever want the history, export a backup first (chapter 6).
